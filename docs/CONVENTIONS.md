# CONVENTIONS.md

## .NET / API

- **Layering:** controllers thin; logic in Application services; invariants in Domain.
  No EF Core types leak into Api or Domain.
- **DTOs:** never expose entities over HTTP. Map entity ⇄ DTO. Request DTOs validated
  with FluentValidation.
- **Async everywhere:** `async`/`await`, `CancellationToken` on all I/O.
- **Errors:** throw domain exceptions; a global exception middleware maps them to
  ProblemDetails (400 validation, 403 authz, 404 not found, 409 rule violation).
- **Money:** `decimal` only; EF mapping `numeric(18,2)`. Recompute totals server-side.
- **Dates:** store/compare in UTC (`DateTime` kind=Utc) via `IClock`. Display formatting
  is a frontend concern.
- **IDs:** `Guid` PK set in the entity constructor; `Code` via `ICodeGenerator`.
- **Migrations:** one EF migration per slice, named `Slice0X_<feature>`. Never edit a
  shipped migration; add a new one.
- **Auth:** `[Authorize(Policy=...)]` on endpoints; resource checks for vendor scoping.
- **Naming:** PascalCase types/methods, camelCase locals, `I`-prefixed interfaces,
  `*Command`/`*Query`/`*Service` for use-cases, `*Dto` for DTOs.

## React / web

- **TypeScript strict.** No `any`. API types come from `web/src/api/schema.ts`
  (generated by `npm run gen:api`); do not hand-write request/response shapes.
- **Server state via TanStack Query** (`useQuery`/`useMutation`); no manual fetch in
  components. Local UI state via `useState`/`useReducer`. No global store unless needed.
- **No business logic in the client.** The UI may *display* a rule's result (e.g. grey
  out a closed RFQ's submit button) but the server is the authority.
- **Components:** functional + hooks; one component per file; colocate component + test.
- **Styling:** reuse the prototype's design tokens (see ARCHITECTURE). Square corners;
  Inter body / Georgia titles+numerals.
- **No `localStorage` for domain data** — only the JWT/session token.

## Testing

- **API (xUnit + FluentAssertions):** every business rule in BUSINESS-RULES.md has at
  least one passing-path and one rejected-path test. Use EF Core InMemory or a Testcontainers
  Postgres for repository tests. Name tests `Method_Scenario_Expectation`.
- **Web (Vitest + Testing Library):** test that screens render, mutations call the right
  endpoint, and rule-driven UI states (disabled submit after close, masked names) show.
- **Definition of done for a slice:** `dotnet test` green, `npm run test` green, app runs
  on localhost, and the "verify" checklist in the slice passes.

## Git

- One branch per slice: `slice/0X-<feature>`. Conventional commits
  (`feat:`, `fix:`, `test:`, `chore:`). Small, reviewable commits.
